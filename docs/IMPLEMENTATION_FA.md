# راهنمای پیاده‌سازی — دورهمی‌یار ۰٫۲٫۰

این سند **وضعیت واقعی کد** را توصیف می‌کند، نه آرزوها. هر ادعا با برچسب وضعیت مشخص شده است:

- **[پیاده‌سازی‌شده]** — در کد هست و اجرا می‌شود.
- **[هدف]** — طراحی شده، در کد نیست.
- **[نیازمند آزمون]** — کد هست ولی آزمون خودکار پوشش نمی‌دهد (آزمون دستی لازم است).

---

## ۱. اجرا

```bash
npm start      # سرور روی http://localhost:4173  (PORT قابل تغییر است)
npm test       # ۲۴۶ آزمون
npm run check  # بررسی یکپارچگی (نحو، رجیستری، دارایی‌ها، نسخه) + آزمون‌ها
```

بدون هیچ وابستگی بیرونی (بدون `npm install`). Node ≥ ۲۰.

## ۴. مدل امنیتی

- **سرور**: فقط `public/` را سرو می‌کند؛ `/package.json`, `/tests/*`, `/.git/*` با **۴۰۳** رد می‌شوند. `x-frame-options`, `nosniff`, `permissions-policy`, `CSP` روی هر پاسخ. آزمون: `tests/server.test.js`.
- **پیام‌های چندگوشی**: `validateMessage` (و همان قاعده در سرور) نسخه، نوع مجاز، قالب کد اتاق، طول فرستنده، و سقف ۱۶KB را بررسی می‌کند. فهرست انواع پیام در سرور و کلاینت **یکی** است (`hello, welcome, state, action, ack, ping, pong, bye, error, presence, seat, start, move, sync`) — آزمون هم‌خوانی در `tests/table-live.test.js`.
- **اختیار میزبان با رمز**: اتاق `hostToken` جداگانه دارد. فقط اتصالی که آن را ارائه کند `isHost` می‌شود. **ترتیب اتصال هیچ اختیاری نمی‌دهد** و با رفتن میزبان، اختیار خودبه‌خود منتقل نمی‌شود. آزمون: «بدون رمز میزبان، هیچ‌کس نمی‌تواند وضعیت پخش کند» و «انتقال اختیار میزبان با رفتن او رخ نمی‌دهد».
- **وضعیت بازی**: `createRevisionGate` فقط پیام `state` از **میزبان** و با `revision` بزرگ‌تر از آخرین مقدار را می‌پذیرد.
- **کارت‌ها هرگز روی شبکه نمی‌روند**: فقط «دانه» و فهرست صندلی‌ها می‌رود؛ هر دستگاه با `seededShuffle(fullDeck(), seed)` همان ۵۲ کارت را می‌سازد. آزمون: حجم پیام `start` حدود ۲۵۰ بایت و بدون `suit`/`rank`.
- **پنهان‌سازی**: `viewFor` دست بیننده را کامل و بقیه را ماسک می‌کند؛ `publicState` همه را ماسک می‌کند و `stock` را هم پنهان می‌کند. آزمون: `tests/table.test.js`.
- **محتوای مخفی مافیا**: نقش‌ها هرگز در پیام عمومی نمی‌روند؛ پردهٔ خصوصی با `data-private` و رویداد `dy:hide` روی `visibilitychange` بسته می‌شود.

## ۵. اختلاف سند ↔ کد (گزارش صادقانه)

| ادعای سند | واقعیت کد |
|---|---|
| «بازی آنلاین ۲+ گوشی روی بلوتوث/Wi-Fi/اینترنت» | اینترنت/هم‌شبکه **هست** (رلهٔ WebSocket + اتاق کددار). Nearby/بلوتوث **نیست**. |
| «اتاق با کد روی سرور» | **هست** — `POST /api/room` و `GET /api/room/:code`. اتاق‌ها در حافظه‌اند (۶ ساعت TTL) و با ری‌استارت سرور پاک می‌شوند. |
| «تصویر هنری برای هر کارت و هر بخش» | ۲۳ دارایی؛ ورق‌های تصویری شش تصویر جدا دارند. آس‌ها، تختهٔ دوز و جفت تصویر «تفاوت را پیدا کن» **هنوز نیست**. |
| «تست هوش و کوییز با بانک بزرگ» | کوییز ۵۰ سؤال، هوش ۱۶، چیستان ۲۶. عدد «۵۰۰ سؤال» در کد نیست. |
| «همگام‌سازی ابری آمار» | وجود ندارد؛ همه‌چیز در `localStorage` با پیشوند `dy:`. |
| «میز حکم کامل با ۱۳ دور و امتیازدهی» | میز و نوبت و امتیاز **هست**؛ ولی پایان رسمی بازی (۷ امتیاز) و حکم‌خوانی (مناقصه) در UI شبکه‌ای **هنوز نه** — حالا فقط با حکم پیش‌فرض شروع می‌شود. |
| «همهٔ بازی‌ها آنلاین‌اند» | فقط حکم/کم‌ورق/مافیا دکمهٔ «میز» دارند؛ بقیه محلی‌اند. |

## ۶. کارهای باقی‌مانده (به ترتیب اولویت)

1. **[هدف] کامل‌کردن میز حکم**: مناقصهٔ حکم، تعیین ۷ امتیاز برای پایان، و تعویض صندلی بین دورها.
2. **[هدف] میز برای بقیهٔ بازی‌های چندنفره**: دوز، مافیا (با نقش‌های خصوصی روی گوشی هرکس)، اسم و فامیل.
3. **هنر اختصاصی**: آس‌های گوتیک ×۴، تختهٔ دوز با نقش‌مایهٔ چینی، جفت تصویر نقاشی اروپایی برای «تفاوت را پیدا کن»، تختهٔ مار و پله.
4. **افزودن محتوا**: کوییز ۵۰ → ۱۵۰، چیستان ۲۶ → ۶۰.
5. **دسترس‌پذیری**: آزمون با اسکرین‌ریدر فارسی و بزرگ‌نمایی ۲۰۰٪.
6. **[نیازمند آزمون] آزمون دستی روی دو گوشی واقعی** — همهٔ آزمون‌های شبکه در Node با دو کلاینت واقعی WebSocket اجرا می‌شوند، ولی رفتار iOS Safari (خواب‌رفتن تب، قطع Wi‑Fi) آزموده نشده است.
7. **[هدف] شبیه‌سازی عنوان‌های باقی‌مانده**: Arkham Horror LCG، This War of Mine، Robinson Crusoe، Spirit Island، LOTR LCG. (Gloomhaven و Onirim اکنون الهام‌بخش وردِن و دروازه‌های رؤیا شده‌اند.)

## ۷. قرارداد افزودن بازی جدید

```js
// public/src/games/myGame-ui.js
export function mountGame(root, { game, onExit }) {
  let state = { screen: 'intro' };
  const draw = () => h('div', {}, /* ... */);
  const render = () => mount(root, draw());
  render();
  return () => { /* پاک‌سازی تایمرها */ };
}
```

سپس در `registry.js` یک ورودی با `id`, `title`, `meta`, `art`, `cats`, `solo`, `badge`, `multi`, `load` اضافه کن و فایل را به `SHELL` در `sw.js` و به فهرست `scripts/check.mjs` ببر. `npm run check` هر سه را بررسی می‌کند.
