# راهنمای پیاده‌سازی — دورهمی‌یار ۰٫۲٫۰

این سند **وضعیت واقعی کد** را توصیف می‌کند، نه آرزوها. هر ادعا با برچسب وضعیت مشخص شده است:

- **[پیاده‌سازی‌شده]** — در کد هست و اجرا می‌شود.
- **[هدف]** — طراحی شده، در کد نیست.
- **[نیازمند آزمون]** — کد هست ولی آزمون خودکار پوشش نمی‌دهد (آزمون دستی لازم است).

---

## ۱. اجرا

```bash
npm start      # سرور روی http://localhost:4173  (PORT قابل تغییر است)
npm test       # ۱۰۴ آزمون
npm run check  # بررسی یکپارچگی (نحو، رجیستری، دارایی‌ها، نسخه) + آزمون‌ها
```

بدون هیچ وابستگی بیرونی (بدون `npm install`). Node ≥ ۲۰.

## ۴. مدل امنیتی

- **سرور**: فقط `public/` را سرو می‌کند؛ `/package.json`, `/tests/*`, `/.git/*` با **۴۰۳** رد می‌شوند. `x-frame-options`, `nosniff`, `permissions-policy`, `CSP` روی هر پاسخ تصویری/HTML. آزمون: `tests/server.test.js`.
- **پیام‌های چندگوشی**: `validateMessage` نسخه، نوع مجاز، قالب کد اتاق، طول فرستنده، و سقف ۱۶KB را بررسی می‌کند. پیام نامعتبر بی‌صدا دور ریخته می‌شود.
- **وضعیت بازی**: `createRevisionGate` فقط پیام `state` از **میزبان** و با `revision` بزرگ‌تر از آخرین مقدار را می‌پذیرد — کلاینت نمی‌تواند وضعیت را به عقب یا از طرف خودش جلو ببرد.
- **محتوای مخفی**: نقش‌ها/واژه‌ها هرگز در پیام عمومی نمی‌روند؛ در مافیا پرده‌ی خصوصی با `data-private` و رویداد `dy:hide` روی `visibilitychange` بسته می‌شود.
- **تصمیم‌های بازی** در حالت آفلاین کاملاً روی دستگاه است (تک‌دستگاهی/چرخشی)؛ در حالت آنلاین **[هدف]** داوری سمت میزبان/سرور.

## ۵. اختلاف سند ↔ کد (گزارش صادقانه)

| ادعای سند | واقعیت کد |
|---|---|
| «بازی آنلاین ۲+ گوشی روی بلوتوث/Wi-Fi/اینترنت» | فقط `BroadcastChannel` (تب‌های همان مرورگر). Nearby/WebRTC پیاده نشده. |
| «اتاق با کد روی سرور» | سرور فقط `/api/health` دارد. |
| «تصویر هنری برای هر کارت و هر بخش» | ۱۰ تصویر برای ۱۰ بخش؛ کارت‌های نقش مافیا تصویر دارند (mafia/citizen/doctor/detective)، ولی ۴ بازی هنر اختصاصی ندارند. |
| «تست هوش و کوییز با بانک بزرگ» | کوییز ۵۰ سؤال، هوش ۱۶ سؤال، چیستان ۲۶. عدد «۵۰۰ سؤال» در اسناد قدیمی نیست. |
| «همگام‌سازی ابری آمار» | وجود ندارد؛ همه‌چیز در `localStorage` با پیشوند `dy:`. |

## ۶. کارهای باقی‌مانده (به ترتیب اولویت)

1. **[هدف] transport واقعی چندگوشی** — WebRTC DataChannel + سرور سیگنالینگ کوچک (`/api/room/:code`). قرارداد در `src/net/sync.js` آماده است.
2. **[هدف] Nearby Connections برای اندروید** — نیازمند Play Services؛ در بسته‌ی PWA ممکن نیست، فقط در پوسته‌ی بومی.
3. **هنر اختصاصی**: `hokm-king`, `snake-board`, `codenames-spy`, `quiz-paper` (سقف تولید تصویر در هر نوبت ۱۰ عدد است — در نوبت بعد تولید شود). تا آن زمان بازی‌ها از بافت‌های موجود استفاده می‌کنند و هیچ URL شکسته‌ای وجود ندارد.
4. **افزودن محتوا**: کوییز ۵۰ → ۱۵۰، چیستان ۲۶ → ۶۰.
5. **دسترس‌پذیری**: آزمون با اسکرین‌ریدر فارسی و بزرگ‌نمایی ۲۰۰٪.
6. **[نیازمند آزمون] آزمون دستی بازی‌ها روی گوشی واقعی** (لمس، اندازه‌ی هدف، ارتفاع امن iOS).

## ۷. قرارداد افزودن بازی جدید

```js
// public/src/games/myGame-ui.js
export function mountGame(root, { game, onExit }) {
  let state = { screen: 'intro' };
  const draw = () => h('div', {}, /* ... */);
  const render = () => mount(root, draw());
  render();
  return () => { /* پاک‌سازی تایمرها */ };
}
```

سپس در `registry.js` یک ورودی با `id`, `title`, `meta`, `art`, `cats`, `solo`, `badge`, `multi`, `load` اضافه کن و فایل را به `SHELL` در `sw.js` و به فهرست `scripts/check.mjs` ببر. `npm run check` هر سه را بررسی می‌کند.
