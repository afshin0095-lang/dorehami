## ۲. پروژه چیست؟

**دورهمی‌یار (Dorehmi-Yar)** — «گوشی وسط، جمع روشن.»

یک دنیای سرگرمی فارسی و RTL که در چهار موقعیت کار می‌کند:

1. **تنهایی** — معما، واژه، حافظه، رکورد شخصی (کاملاً آفلاین).
2. **دو‌نفره روی یک گوشی** — گوشی دست‌به‌دست می‌شود یا روی میز می‌ماند.
3. **جمع حضوری روی یک گوشی** — پانتومیم، اسم‌و‌فامیل، مافیا، دوراهی، و…
4. **چند‌موبایلی** — نزدیک با `Nearby Connections` (اندروید بومی) یا از راه دور با اتاق اینترنتی سبک.

گوشی نقش **کارت، تایمر، داور امتیاز و راوی مافیا** را دارد؛ هدف این است که بعد از شروع، گوشی کمتر دیده شود و جمع بیشتر.

**وعدهٔ عملیاتی:** از باز کردن برنامه تا اولین کارت، کمتر از ۳۰ ثانیه، بدون حساب کاربری، بدون آموزش اجباری، بدون اینترنت.

## ۳. اصول غیرقابل‌مذاکره (از فصل ۱٫۴)

1. شروع فوری؛ بدون ثبت‌نام، مخاطبین یا آموزش طولانی.
2. **Local-first، نه Offline-only:** بازی پایه و بستهٔ شروع بدون اینترنت؛ شبکه فقط برای بازی از راه دور یا بستهٔ اختیاری.
3. چهار شیوهٔ بازی (تکی / دو‌نفره / گروهی یک‌گوشی / چندموبایلی).
4. محتوای متناسب با فضا (خانوادگی ≠ دوستانه) با برچسب روشن.
5. کیفیت بصری ممتاز ولی روان روی گوشی میان‌رده.
6. اینترنت سبک: فقط رویداد/امتیاز/وضعیت اتاق، بدون ویدئو و استریم.
7. درآمد بدون خراب‌کردن بازی: تبلیغ وسط نوبت/تایمر/رأی‌گیری/کارت خصوصی ممنوع.
8. قواعد روشن و دسترس‌پذیر (RTL، متن بزرگ، کاهش حرکت، TalkBack).

**بدون AI اجباری:** هیچ حلقهٔ بازی، رکورد یا چالش روزانه به API پولی وابسته نیست. محتوا از فایل‌های بازبینی‌شدهٔ محلی می‌آید.

## ۵. چطور ساخته می‌شود؟ (معماری هدف)

### ۵.۱ دو مسیر موازی

```
dorehami/
├── index.html, src/, sw.js, manifest.webmanifest, server.mjs   ← PWA وب (مسیر اصلی و سریع‌ترین)
├── android/                                                    ← اپ بومی Kotlin + Jetpack Compose + Nearby
├── tests/                                                      ← node:test برای منطق خالص
├── scripts/                                                    ← check-release-metadata.mjs و …
└── docs/                                                       ← همین سه سند + architecture.md + QA.md
```

- **وب:** JavaScript مدرن با ES modules، `"type": "module"`، Node.js ۲۰+؛ سرور `server.mjs` با ماژول‌های داخلی Node (بدون وابستگی npm)، allow-list فایل‌های عمومی، API اتاق و WebSocket؛ PWA با Service Worker و آرت SVG محلی.
- **اندروید:** Kotlin + Compose، ViewModel + StateFlow، هر بازی یک ماشین حالت مستقل، DataStore برای تنظیمات، Room فقط برای تاریخچه/نشست، Nearby Connections برای چند‌گوشی نزدیک.
- **تست:** `node --test tests/*.test.js` برای منطق خالص، و smoke testهای Kotlin/JVM با `kotlinc` برای قوانین بومی.

### ۵.۲ ماژول‌های وب (فصل ۳۴٫۲ — قرارداد فایل)

| فایل | مسئولیت |
|---|---|
| `index.html` | پوستهٔ PWA، mount pointها، modal/toast/confetti |
| `src/app.js` | orchestrator رابط و state — منطق خالص تازه را در آن انباشته نکن |
| `src/styles.css` | design tokens، تم روشن/تاریک، RTL، انیمیشن، reduce-motion |
| `src/content.js` | کاتالوگ ۱۶ بازی + بانک‌های محلی محتوا (`id` پایدار = کلید رکورد/علاقه‌مندی/چالش) |
| `src/engine.js` | utilityهای خالص: shuffle، برندهٔ سه‌تا، نرمال‌سازی فارسی، انتخاب بدون تکرار |
| `src/mafia-engine.js` | ماشین حالت مافیا (شب/روز/رأی/شرط برد) |
| `src/visual-puzzle.js` | قوانین پازل لغزشی، چیدمان قابل‌حل، راهنما، امتیاز |
| `src/progression.js` / `daily-challenge.js` / `personal-records.js` | XP و نشان، چالش روزانهٔ deterministic، رکوردها و تاریخچه |
| `src/session-storage.js` | snapshot نسخه‌دار + پاک‌سازی مراحل محرمانه هنگام resume |
| `src/room-engine.js` / `room-client.js` / `room-store.js` / `room-invite.js` | اتاق authoritative، کلاینت، ذخیرهٔ اتمیک، لینک دعوت |
| `server.mjs`, `sw.js` | static + API + WS؛ کش پوسته (API نباید به HTML آفلاین تبدیل شود) |
| `assets/art/*.svg` | هنر برداری محلی کارت‌ها |

### ۵.۳ قواعد معماری که نباید شکسته شوند

- **یک منبع حقیقت برای state:** امتیاز/زمان/بازیکن فعال/کارت فعلی از یک state معتبر مشتق شوند.
- **قوانین جدا از UI:** reducer/machine بدون UI اجرا و unit test شود؛ کامپوزبل‌ها قانون را تغییر ندهند.
- **تایمر با deadline، نه شمارش callback در هر ثانیه**؛ پایان تایمر idempotent باشد.
- **Server is authority** در آنلاین؛ در Nearby میزبان مرجع است و پیام هر peer با policy بررسی می‌شود.
- **حریم state خصوصی:** نقش مافیا / کارت پانتومیم از `SessionSummary`، اشتراک‌گذاری، logcat، اعلان و Recent Apps جدا باشد؛ در `ON_STOP` اول پردهٔ خنثی.
- **idempotency:** هر `ScoreEvent` شناسهٔ یکتا؛ نه لمس دوبار، نه reconnect، امتیاز را دوبار ثبت نکند.
- **هر فایل جدید وب** باید در allow-list `server.mjs` و در صورت لزوم precache `sw.js` ثبت شود؛ وگرنه در اجرا یا آفلاین می‌شکند.
- **هماهنگی نسخه:** `package.json`، `android/app/build.gradle.kts`، `CHANGELOG.md`، `/api/health` و نام کش Service Worker هم‌زمان جلو بروند (`scripts/check-release-metadata.mjs`).

### ۵.۴ دستورهای رسمی (فصل ۴۰٫۱)

```bash
npm run check     # نحو JS + check:release + check:android + smoke testهای native + همهٔ تست‌های Node
npm start         # http://localhost:4173

npm test              # node --test tests/*.test.js
npm run check:release # هماهنگی نسخه، metadata، allow-list، کش
npm run check:android # بررسی استاتیک اسکلت/مجوزهای Android و Nearby
npm run test:android-games
```

اندروید (ویندوز/PowerShell، از پوشهٔ `android/`): `.\setup-gradle.ps1` سپس `.\build-debug.ps1`.

- جهت هنری: **«اتاق بازی مدرن» / Joyful Premium Playground** — گرم، کارت‌های بزرگ با گوشهٔ نرم، سایهٔ کنترل‌شده، نه داشبورد اداری نه نئون سراسری.
- پالت: `Ink #201B35`، `Night #151325`، `Paper #FFF9F0`، `Violet #7667F8` (برند/CTA)، `Coral #FF6B6B`، `Citrus #FFD166`، `Mint #48C9A5`، `Sky #53C7EC`.

## ۷. قدم اول پیشنهادی

با توجه به اینکه کد پایه در دسترس نیست، دو مسیر منطقی وجود دارد:

**مسیر ۱ — بازسازی هستهٔ وب از صفر (پیشنهاد من):**
اسکلت PWA (`package.json` با `type: module`، `index.html`، `src/styles.css` با design tokenها، `src/content.js` با ۴–۸ بازی شروع، `src/engine.js`، `server.mjs`، `sw.js`) + `npm test` سبز به‌عنوان اولین تحویل قابل‌اثبات. بعد مافیا و اتاق‌ها روی آن سوار می‌شوند.

**مسیر ۲ — شروع بومی اندروید:** اگر هدف نهایی انتشار در Play/بازار/مایکت است و Nearby اولویت دارد، اسکلت Gradle + Compose + یک بازی کامل (مثلاً پانتومیم) اول ساخته شود.

در هر دو مسیر، ترتیب کاری ثابتِ کتاب مقدس (فصل ۴۳) این است:

1. قاعدهٔ خالص + تست → ۲. منطق/موتور → ۳. UI و state flow → ۴. `npm run check` → ۵. افزایش نسخه و CHANGELOG → ۶. گزارش محدودیت‌های تست واقعی.

و هیچ‌کدام از این‌ها «انجام‌شده» اعلام نشود مگر کد + تست سبز + ذکر محدودیت‌ها با هم باشند.
